# nightfall!punk v1.7D — Cleave Build Ledger

## Purpose
v1.7D cleaves in both senses: bind the code that has earned architectural/evidential support, and cut unsupported defaults away from the incumbent path. It is the cumulative child of restored v1.7C.

## Build doctrine
- Preserve interfaces more readily than implementations.
- Authoritative truth, actor belief, derived caches, and observability are distinct state owners.
- Viewer/debug code is read-only with respect to authority.
- Hard UISR invariants outrank aggregate scores.
- PUR rewards visible playable value per complexity but cannot override truth/invariant gates.
- Unresolved work remains explicit pending state; computation-budget exhaustion is not a world answer.

## Cleave dispositions
### PROMOTE
- snapshot/transaction authority;
- topology/material authority separation;
- separate confidence calibration;
- lexicographic utility incumbent;
- deterministic reason traces;
- versioned derived-cache dependencies.

### RETAIN EXPERIMENTAL
- dependency-component Purple;
- causal cascades/frontier policies;
- adaptive refinement/reaggregation.

### DISABLE
- diffuse distributed-belief challenger as default runtime path.

### PRUNE
- global scalar-priority arbitration as universal conflict resolver.

## Coding determinations resolved in v1.7D
1. Authoritative same-tick reads use the v1.7B snapshot contract.
2. Transaction conflicts are grouped as connected components, not one global queue.
3. Noninteracting transactions remain outside conflict sets.
4. Conflict-set membership is derived from actual read/write hazards and domain rules.
5. Transforming operations remain distinct from mergeable additive operations.
6. Derived caches declare dependency masks explicitly.
7. Unrelated authoritative writes do not invalidate a cache.
8. Relevant component-version changes invalidate dependent caches deterministically.
9. Cache validity never substitutes for authoritative truth.
10. Budget ownership is domain-scoped.
11. Each domain receives a guaranteed floor.
12. Unused domain budget can be returned to shared surplus.
13. Borrowing is explicitly accounted per domain.
14. Emergency reserve is available only for critical work.
15. Budget denial means defer/pending, never fabricate completion.
16. Consequential reason traces declare which provenance fields are present.
17. Absence and zero-valued data are not conflated.
18. Consequential traces require evidence, belief, contract, affordance, transaction, and confidence channels.
19. Nonconsequential debug traces may be incomplete.
20. Evidence maturity is encoded H0 conceptual through H4 player-supported.
21. Evidence level and runtime disposition are separate dimensions.
22. A subsystem can remain architecturally valid while retained experimental.
23. A failed implementation does not automatically invalidate its interface or hypothesis family.
24. v1.7D promotes calibration without claiming H3 runtime or H4 player evidence.
25. Purple/cascade/refinement remain H0 until dedicated physical corpora exist.
26. Read-only observability is a code contract, not a UI convention.
27. Observing a frame must not change the authoritative state hash.
28. PLAY/WORLD/ACTOR/CAUSAL/FULL are overlay masks over one data source, not separate simulation paths.
29. WORLD overlays expose material/spatial authority.
30. ACTOR overlays expose evidence/belief/confidence/contract context.
31. CAUSAL overlays expose transactions/conflicts/Purple/frontier/refinement/reason traces.
32. FULL is composition of WORLD + ACTOR + CAUSAL.
33. Presentation presets do not own simulation state.
34. Observer ON/OFF parity is a metamorphic regression requirement.
35. Debugging configuration cannot force unresolved winners.
36. Semantic-only connectivity cannot create physical authority.
37. Challenger runtime paths are disabled by default in the Cleave build.
38. Incumbent paths are selected by policy data rather than scattered compile-time assumptions.
39. v1.7A/B/C source is integrated into normal CMake/CTest in v1.7D.
40. Standalone cumulative regression remains available to verify historical trajectory independently of CMake.

## Exit criteria toward v1.7E
v1.7D is ready to hand off when:
- A -> B -> C -> D regression passes;
- CMake/CTest composes the restored 1.7 lineage;
- viewer-observation contracts are demonstrably read-only;
- conflict sets, versioned caches, and budget borrowing are deterministic;
- promoted/experimental/disabled/pruned statuses are inspectable;
- no graphical presentation code is required to mutate game authority.

## Scientific interpretation
v1.7D is primarily a code-organization and observability build. It should not be credited with new player-performance gains merely because architecture is cleaner. Its positive claim is stronger separation of concerns, falsifiability, reproducibility, and lower risk of hidden coupling.
