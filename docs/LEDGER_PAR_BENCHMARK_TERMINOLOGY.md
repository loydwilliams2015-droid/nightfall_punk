## Definition

**PAR** uses the ordinary word **par**, as in **“on par”** and **“par sheet.”** It is **not an acronym**.

In nightfall!punk, PAR means evaluating a subsystem, feature, experience, or build against an explicit comparative benchmark sheet so that the project can become **on par with, or meaningfully advance beyond, relevant peer standards while remaining architecturally itself**.

PAR is therefore a relation of **comparative adequacy, mutual sharpening, and collective flourishing**, not a winner-take-all ranking system.

Canonical formulation:

```text
PEER / REFERENCE WORK
        +
OBSERVED MECHANISM / QUALITY
        +
NIGHTFALL CURRENT STATE
        +
MEASURED GAP / DIFFERENCE
        +
PROJECT-SPECIFIC SYNTHESIS
        +
PROOF
        =
PAR EVALUATION
```

## Par sheet

A **par sheet** is a structured comparison record. It should state, where relevant:

```text
PAR-SHEET ID
SUBSYSTEM / FEATURE / EXPERIENCE
REFERENCE GAME(S) / SOURCE(S)
REFERENCE TYPE / TYPED AUTHORITY
OBSERVED REFERENCE MECHANISM
WHY IT MATTERS
NIGHTFALL CURRENT STATE
COMPARABLE DIMENSION(S)
MEASURE / HUMAN OBSERVATION
GAP / DIFFERENCE
NIGHTFALL-SPECIFIC TARGET
NEGATION / WHAT NOT TO COPY
TEST / PROOF
RESULT
PAR DISPOSITION
```

Suggested dispositions:

```text
MEETS PAR
EXCEEDS PAR ON STATED DIMENSION
BELOW PAR / GAP REMAINS
DIFFERENT-BUT-COMPARABLY-VALID
NOT COMPARABLE / N-A
INSUFFICIENT EVIDENCE
```

Do not use “above par” or “below par” as loose global quality labels when the comparison is multidimensional. Prefer precise statements such as:

```text
MEETS PAR on camera responsiveness
BELOW PAR on visual legibility under surge load
EXCEEDS PAR on bounded actor epistemology
DIFFERENT-BUT-COMPARABLY-VALID on navigation architecture
```

## Collective flourishing / iron sharpening iron

PAR comparisons are **non-zero-sum**.

The project compares itself with other games because strong games make other games stronger:

```text
OTHER GAME demonstrates a useful mechanism
-> nightfall studies it
-> nightfall reaches comparable functional quality through its own architecture
-> nightfall may discover a new mechanism or synthesis
-> that contribution can in turn become useful comparative material for others
```

This is the project meaning of **collective flourishing** and **iron sharpening iron** in comparative design.

The purpose is not:

```text
copy reference
rank all games on one ladder
prove nightfall universally superior
```

The purpose is:

```text
recognize demonstrated strengths
identify real gaps
learn without surrendering ontology
contribute distinct improvements
raise the practical design standard through comparison
```

## Relation to Protocol 3 reference evidence

PAR uses external games and other references as **typed inductive evidence**.

A peer game can provide strong evidence that:

- a mechanism is technically or experientially achievable;
- a particular failure has known alternatives;
- a design relation can be made legible;
- a subsystem can meet a demonstrated performance or usability standard;
- a nightfall hypothesis is strengthened, weakened, bounded, or contradicted.

But a peer game does **not** automatically establish a deductive truth for nightfall.

Canonical boundary:

```text
REFERENCE GAME / PAR SHEET
        -> COMPARATIVE / MECHANISM EVIDENCE
        -> may validate or invalidate INDUCTIVE REASONS
        -> may generate hypotheses / tests / targets
        -X-> does not silently become PROJECT PREMISE
```

Reference authority remains typed and domain-bounded.

Examples:

- *Titanfall* can be high-authority mechanism precedent for responsive movement-combat coupling without owning nightfall movement ontology.
- *Alien: Isolation* can be high-authority comparative evidence for legible persistent predator search without proving how Dream Cattlers must work.
- *Prey (2017)* can establish strong systemic-environment precedent without requiring nightfall to copy its object architecture.
- *Quake* can establish an important par standard for immediate spatial/weapon readability without making arena conventions universal laws.

## PAR is dimension-specific

A game or build is almost never simply “on par” in every respect.

PAR should normally be stated against dimensions such as:

```text
responsiveness
causal coherence
AI legibility
bounded epistemology
movement quality
combat readability
physics affordances
systemic interaction
network robustness
performance tails
accessibility
visual clarity
audio clarity
world persistence
player agency
maintenance / implementation cost
```

This is compatible with Protocol 2/3 multidimensional value analysis: a subsystem can meet par on one dimension while remaining intentionally different or below target on another.

## PAR and originality

Meeting PAR does not mean feature parity by imitation.

Preferred relation:

```text
REFERENCE FUNCTION
-> identify why it works
-> isolate transferable mechanism
-> test against nightfall premises
-> synthesize through existing owners
-> measure nightfall result
```

A nightfall implementation can therefore be **on par in value while structurally different in mechanism**.

Example:

```text
REFERENCE:
excellent squad coordination through shared tactical state

NIGHTFALL:
excellent squad coordination through bounded reports + claims + actor-local belief

RESULT:
potentially MEETS/EXCEEDS PAR on coordination quality
while intentionally differing on epistemic architecture
```

## Questions Subroutine integration

PAR belongs primarily in the PRECEDENT, NIGHTFALL STATE, SYNTHESIS, and PROOF stages:

```text
0 ZERO-FAMILIARITY
1 PRECEDENT          <- what establishes the par benchmark?
2 NIGHTFALL STATE    <- where are we relative to that benchmark?
3 NEGATION           <- what should not be copied?
4 SYNTHESIS          <- how do we reach comparable value through our architecture?
5 UNCERTAINTY GATE
6 PROOF              <- what demonstrates that PAR was actually met?
```

A PAR claim requires evidence. “Comparable in aspiration” is not the same as “meets par.”

## STEWARD rules

1. **PAR is not an acronym.** Do not expand it as Preserve/Await/Reconcile or any other phrase.
2. **PAR is not DEFER.** It does not describe postponement.
3. **PAR is not automatic feature parity.** Compare value/function/mechanism at stated dimensions.
4. **PAR is evidence-bounded.** A par-sheet claim must identify its reference, scope, measurement, and proof status.
5. **PAR is non-zero-sum.** Comparative excellence serves mutual improvement / collective flourishing.
6. **PAR does not override project premises.** Reference games provide typed evidence, not absolute deductive authority.
7. **PAR may be high-priority.** When a subsystem has mature peer precedents, a well-formed par sheet can substantially constrain inductive design reasoning and expose avoidable deficits.

## Maxim

> **PAR asks whether we have reached the demonstrated standard of our peers, learned what makes that standard work, and contributed our own sharpened answer without confusing comparison with imitation.**
