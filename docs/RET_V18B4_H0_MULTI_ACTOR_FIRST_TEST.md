# 1.8B.4 H0 — First Test Build / RET Ledger
Base: build/v18b3-m4-eec-typed-realizers-h0, user-selected source, **not an accepted B3 engine**. This is a standalone C11 *multi-actor arbitration experiment*, not integrated dynamic physical execution or B4 production release.

## Research programme
Question: how do competing actor/object/action claims, shared membership, exclusive capacity, material uncertainty, and snapshot epoch changes affect physically meaningful encounter authorization?
Semantics: eligibility and contingent realization remain distinct (EEC-01). Same-tick grants are prospective; no event declares an A4 impulse, A5 contact/history, inventory transfer, durable reserve or physical completion without actual execution.
Hard invariants: server-authoritative identity; revision-bound permission; unknown material pending; exclusive/shared scoped capacity; deterministic replay; unique grants and no double debit; no phantom material/impulse; retained postcommit history. Same-tick deterministic ID order alone does not prove cross-tick fairness.
Incumbent: M4 material-first B2 + EEC + typed B3 seam; challenger: M3 exhaustive eligibility with identical physical logic; unsafe negative control: naive grant on eligibility flag. **This H0 standalone lab uses IDENTICAL arbitration code for M3/M4 and therefore cannot compare their actual mechanism costs or choose a winner.**
Hypotheses: (H1) bounded arbitration can enforce a local scope; (H2) stale/unknown eligibility refuses positive grants; (H3) deterministic arbitration can replay but actor-ID priority may starve; (H4) integrated physical and network scopes need additional proof.
RET: A priori authorization != physical realization. Formally defined narrow pure comparator and max 64 requests/max 16 slots, without formal proof of global safety. Empirically executed on local isolated C11: 5376 authored cases (256 canonical, 2048 randomized, 512 pathological, 512 boundary, 2048 held-out); M3/M4 status mismatch 0 and stale/unknown/denied positive-grant violations 0; naive negative control 1024 unsafe cases. GCC strict C11 -O2 -Werror and UBSan pass after correcting two initial test-harness compiler diagnostics. Heldout RNG seed 0xB418CAFE. This is NOT a full independent truth oracle nor verified performance: CSV's cpu_ns_total=0 is a placeholder and **must be ignored**. No latency measured. No integrated B3 actual physics tests.
Highly predictable: cheap early rejection can save work only on negative workloads; uncertain: multi-tick fairness, owner integration, exact conflicts, aliasing and resource transfers; unresolved: EEC pending 337/360, B1 archive #37, full B3 physical behavior, B5 persistence, governance/license #36.
Mandatory gates (all OPEN for B4): (1) actual M4 versus independent M3, (2) independent oracle and contest/alias/duplicate tests, (3) real A6 owner and B3 A4/A5 physically executed outcomes, (4) deterministic replay under permutations and sustained cross-tick fairness, (5) conservation and failure-atomic reservation, (6) canonical/random/pathological/boundary/heldout robust corpus with raw evidence, (7) GCC/Clang/ASan/UBSan and whole-engine CI, (8) actual tick/display/network responsiveness, (9) rights/provenance/reviewer acceptance.
Decision: H0 LAB RUN documented; no release exit candidate or merge. M4 held provisionally from B2 lineage, M3 remains challenger. Develop next in this existing repo without misleading feature-completeness claims.
